# Recomposition Repair Lab｜重组问题观察区

> status: OBSERVATION_ONLY
> purpose: 记录 Source→Target 重组过程中可能发生的稳定信息损失，在样本足够之前不修改生产工作流。

## 当前原则

```text
RECORD_FIRST: true
WORKFLOW_REPAIR_NOW: false
SINGLE_CHAPTER_CONCLUSION: forbidden
CURRENT_SAMPLE_COUNT: 1
```

现在只做证据积累，不因为第001章一次结果就重写 `ORIGINAL_RECOMPOSITION`。

后续每跑一章，优先保留三份可对照材料：

```text
SOURCE / 母本具体 Story Moments
OLD_OR_ORIGINAL_RECOMPOSITION / 重组结果
BETTER_OR_ADOPTED_VERSION / 作者认为更好看的版本
```

然后只记录 Delta：

```text
PRESERVED
TRANSFORMED
LOST
```

重点观察某类部件是否跨多章重复丢失。只有形成稳定重复模式后，再统一分析 owning rule 和修复方案。

## 当前待验证假设｜不是结论

第001章暂时暴露出以下可能失血点：

```text
RELATION_SLOT / 已存在的人物关系承载
EXPECTATION_THREAD / 倒计时、等待、反复回返的期待线
OLD_TRAP_PROOF / 为什么主角以前没有翻身的具体证明
REALITY_REPRESSURE / 系统或机会信息中间，现实压力再次发生
PAYOFF_REALIZATION / payoff 被当成一个信息节点，而不是完整兑现过程
DESIRE_ESCALATION / 新机会出现后，人物目标与欲望的升级
```

这些目前全部标记为：

```text
HYPOTHESIS_ONLY
NEEDS_MORE_CHAPTERS
```
