# 技法 02｜爆点展开（五拍为历史示例，不是硬门）

> V3.1 status: advisory only

## 是什么

爽点爆点（突破/重大获得/重大打脸/死亡级事件）不能一句摘要带过，但也不再要求固定拆成“≥5个身体反应”。

旧“五拍”是一个曾经有效的展开示例，用来提醒：**结果发生时要让读者看见触发、确认和局势变化。** 它不是当前生产配额。

## 来源启发

母本的爆点通常不是一句“他升级了”结束，而是：

```text
关键结果出现
→ 当事人反应
→ 旁人/系统/现实证据确认
→ 身份、能力、资源或关系因此改变
```

## 怎么用

优先保证：

```text
1. 触发是真的发生，不是旁白宣布
2. 结果有人/系统/现实证据确认
3. 结果改变了后续局势
```

身体反应、动作、对白、面板都只是可选承载方式。

## 红线

- 禁止“模拟结束，他升到了二阶”式一句摘要吞掉大结果。
- 禁止为了“爆点感”机械堆叠瞳孔、呼吸、指节、出汗、喉结等微动作。
- 禁止把“旧五拍模板”重新解释成 PASS/FAIL。

## 与当前规约

正式生产以 `simulator-novel-production-contract.md` 的 `EMOTION_VISIBLE / SCAN_STORY / BLOCK_PROGRESS` 为准。

## Memory line

> **大爆点要真实发生、被确认、改变局势；五拍只是历史展开范例，不是数量门。**
