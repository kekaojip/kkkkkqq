# 技法 11｜开头与结尾的自然入场/停点

> V3.1 status: advisory only

## 是什么

开头和结尾是叙事工具，不是“多样性 KPI”。

V3.1 起，正式生产不再要求“连续两章不得同型”，也不再按 SIM / REALITY / MIX 规定固定开头或结尾。

真正需要守住的是：

```text
开头：尽快进入当前事情或明确目标
结尾：当前有效剧情第一个自然闭合点即停
```

## 开头可选手法

```text
OPENING_DIALOGUE  对白开场
OPENING_EVENT     事件直入
OPENING_OBJECT    关键物件/画面带出事件
OPENING_CONTINUE  承接上章
OPENING_PANEL     系统面板/模拟光幕承接
OPENING_THOUGHT   一句判断直接进事
```

这些只是表达选择，不与 BLOCK_TYPE 绑定。

## 结尾可选手法

```text
ENDING_HOOK
ENDING_FROZEN
ENDING_LINE
ENDING_ACTION
ENDING_AFTERMATH
ENDING_NATURAL
ENDING_BRANCH
ENDING_PANEL
```

系统面板可以合法收尾，只要它本身就是当前真实剧情变化。禁止的是：事情已经结束后，再补一层系统总结、预告或重复确认。

## 红线

- 纯氛围/天象开场若没有承重事件，容易让第一屏看不到剧情。
- 禁止为了“和上一章不一样”硬换开头/结尾形式。
- 禁止为了钩子补尾巴。
- 无钩子自然断章合法。

## 与 BLOCK 的关系

BLOCK_TYPE 只描述大段结构，不拥有开头/结尾模板解释权。块内连续多章同型完全合法，只要事件在推进。

## Memory line

> **不是每章必须换壳，而是每章必须尽快进事、到自然闭合点就停。**
