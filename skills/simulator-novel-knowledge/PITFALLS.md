# 踩坑清单｜PITFALLS

> 知识库的“别踩这些”清单。全部来自实际生产踩坑。历史防线如已被 V3.1 替代，会明确标注，避免旧规则重新进入生产链。

---

## P01 首屏纯氛围/纯环境开场
- 现象：开头先写天色、灯光、远景，读者第一眼看不到人在干什么。
- 当前防线：生产规约“首屏原则” + Plot Block `FIRST_SCREEN_STORY_VISIBLE` + S3 `SCAN_STORY`。
- 说明：不再要求固定“前300字必须对白”；只要求第一屏能抓到事情或明确目标。
- 状态：✅ 已修（V3.1）

## P02 微动作密度（监控摄像头式）
- 现象：几乎每句一个小动作（掏出/数两遍/收回/打结/写字/擦灰），动作本身反而挡剧情。
- 当前防线：human-writing-l2 原包 + Story Compose package-owned repair；S3 不新增“每段必须动作”的机械门。
- 状态：✅ 已修

## P03 心理给过程不给结论
- 现象：长时间写“他盯着看、反复思索”，却迟迟不做决定。
- 当前防线：事件先行、解释后挂；思考只写到足以支撑当前决定；SCAN_COORDINATES 不允许“分析”冒充坐标。
- 状态：✅ 已修（V3.1）

## P04 形容词+动作+心理三件套挤一句
- 现象：修饰、动作、心理同时堆进一句，首读要拆句。
- 当前防线：`CLEAR_FIRST_READ` + Writer/Human Writing 原包表达约束。
- 状态：✅ 已修

## P05 “不是A是B”对比腔（AI检测 blocking）
- 现象：后置否定式对比被 story-deslop 抓 blocking。
- 当前防线：Story Compose Phase 2 / story-deslop 检测 + owning layer 局部修复。
- 状态：✅ 已修

## P06 预告腔收尾
- 现象：章末替读者总结意义、预告下一章、重复确认“新的故事开始了”。
- 当前防线：`ENDPOINT_STOP`：当前有效剧情第一个自然闭合点即停；禁总结/预告/重复系统确认。
- 状态：✅ 已修（V3.1）

## P07 normalize 引号+省略号 bug（工具层）
- 现象：引号后的省略号曾被 normalize 错改。
- 当前防线：normalize 工具层既有修复；本轮不动 Story Compose / story-deslop 本体。
- 状态：✅ 已修

## P08 修辞长句挡剧情
- 现象：一句话挂太多修辞，读者需要回读才知道发生了什么。
- 当前防线：`CLEAR_FIRST_READ`；表达问题交 Story Compose 原包局部修复，不在 S3 再造全文润色。
- 状态：✅ 已修

## P09 情绪只写抽象心理，或反向过度表演
- 旧现象A：重大结果只写“他很激动/他压住狂喜”。
- 旧现象B：为了修A，又发展成瞳孔、呼吸、手指、喉结、出汗层层堆叠的“爆点五拍模板”。
- 旧防线：技法02 + S3 `BURST >=5 beats`。
- V3.1 修正：五拍硬门退役。重大情绪优先通过 `明确决定 > 对白 > 动作 > 身体反应` 可见；身体反应不是默认手段。
- 状态：✅ 已修（V3.1）

## P10 每章强制宣言
- 现象：为了“驱动力”每章硬塞一句狠话，人物开始像固定播报器。
- 旧防线：技法05 + S3 J9 强制 DECLARATION。
- V3.1 修正：DECLARATION 退为可选技法；真正的目标感由人物当前决定和 SCAN_COORDINATES 承担。
- 状态：✅ 已修（V3.1）

## P11 章节缺剧情，被“肉块 KPI”反向补水
- 旧现象：早期章节太短、事件太薄。
- 旧修法：BRAIN≥120、HISTORY≥80、PANEL逐条点评等“肉块必含”。
- 新问题：模型开始为了过表填心理、回忆、面板，剧情反而被解释埋住。
- V3.1 防线：旧肉块硬门整体退役；改用 `SCAN_COORDINATES + BLOCK_PROGRESS + SCAN_STORY`。低于字数底线先查剧情坐标是否太薄，不允许恢复退役肉块机械注水。
- 状态：✅ 已修（V3.1）

## P12 情绪/系统浓度数字化
- 旧现象：把感叹号、面板行数、系统场景数量反向设成目标，模型为了指标补喊叫、补面板、补系统互动。
- 历史数据仍可保留在 `BOOK_ARCHITECTURE_M01.md` 观察用，但不进入 PASS/FAIL。
- V3.1 防线：面板改为 `EVENT_PANEL / LOCATOR_PANEL`；删减测试为“删掉是否损失剧情变化或必要定位”；情绪改 `EMOTION_VISIBLE`，不设数字。
- 状态：✅ 已修（V3.1）

## P13 章节级强制换壳
- 现象：为了制造“变化感”，要求连续两章不能同开头/同结尾，或按 SIM/REALITY/MIX 规定固定开尾。
- 根因：把母本统计结果误当生产因果。
- 母本真实观察：长 SIM 串合法，REALITY 多为短插曲，变化主要来自块转场和块内事件推进。
- V3.1 防线：开结尾类型限制退役；BLOCK_TYPE 只描述结构，不决定格式。开头只要求快速入事，结尾只要求自然停点。
- 状态：✅ 已修（V3.1）

## P14 无块碎串｜当前块没兑现就频繁切形态
- 现象：当前大目标尚未完成，却为了“新鲜感”不断在模拟/现实/系统形态之间切换；每章都像新开一个壳，长线推进被切碎。
- 根因：没有 BLOCK 层，章节级多样性规则越权管理长篇结构。
- 当前防线：`CURRENT_BLOCK` 六字段 + 可判定 `BLOCK_EXIT_CONDITION`；S2 每章开头只检查 EXIT 是否达成，未达成就继续推进 `BLOCK_PROMISE`。
- 关键纪律：BLOCK 不设章数配额；EXIT 可因新剧情事实细化，但必须记录 `EXIT_CONDITION_REVISION_REASON`。
- 状态：✅ V3.1 新防线

## V3.1 当前核心防线总表

```text
BLOCK              管这一大段兑现什么
SCAN_COORDINATES   管这一章真正发生什么
SCAN_STORY         管读者扫过去看不看得见
CLEAR_FIRST_READ   管表达是否需要回读
ENDPOINT_STOP      管有没有越界/补尾巴
CHAPTER_LENGTH     只管1900-2500正常区间与1500硬底线
```

以下旧生产 KPI 已退役：

```text
BRAIN/HISTORY 字数下限
PANEL_LINES 数量/区间
SYSTEM_SCENES 数量下限
EXCLAMATION 数量/区间
DIALOGUE 百分比目标
BURST 五拍硬门
每章强制 DECLARATION
按 SIM/REALITY/MIX 强制开头/结尾
```

## 清单维护规则

```text
踩了新坑 → 追加条目 + 标注当前防线
旧防线被替代 → 必须写明“历史规则 / 当前规则”，避免旧规则复活
坑修好 → 状态改 ✅ 已修，保留记录供复盘
```
