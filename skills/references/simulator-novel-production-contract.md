# Simulator Novel Production Contract｜模拟器文生产规约

> status: production-main
> role: 本书系工作流的专用生产规约（模拟器文 / 系统流 · 番茄向）
> applies_to: S1 / S2 / S3 全链（Story Compose 黑盒内部不动，本规约只在上游输入与硬复核生效）
> basis: 母本《一年抽取一词条，模拟的也可以？》第1章 + 《高武：人到中年…》第1章 拆解结论
> authority: TARGET 真值 > 本规约 > 泛网文默认

## 0. 为什么有这个文件

模拟器文有自己的读者契约：**面板、出货、赌狗心态、快节奏、强声口**。通用"自然好读"约束写不出这种书。本规约把模拟器文必须的写法要求固化到上游（剧情块/人物块/输入包），让 Story Compose 原包拿到"能写出模拟器文"的输入，而不是靠生成器自由发挥。

## 1. 人物声口契约（S2 人物块必带）

主角必须是"网文读者"人设（番茄/起点老读者），满足：

```text
VOICE_PLAYFUL: 口语化、会玩梗（"这波血赚""赌了""欧了""非了"），密度适中不尬
VOICE_EXPRESSIVE: 心理外放，狂喜/崩溃直接写，不用"压住情绪"式含蓄叙事
VOICE_META: 对系统文/模拟器文套路有认知，能自己解说金手指（meta 幽默，一处一章足够）
VOICE_COMRADE: 必须有至少一个同伴角色（话痨/憨厚/仗义），开场第一句用对白带出他
```

禁止：

```text
苦情隐忍型主角（模拟器文要的是爽不是苦）
全程无心理活动、无吐槽的"行动机器"
只有主角没有"活人配角"
```

## 2. 剧情块节拍（S2 剧情块必带）

模拟器文章节节奏，必须标注每个镜头的快慢：

```text
FAST: 铺垫/日常/压榨/背景 → 一段带过，不恋战
MID: 触发/面板/决策 → 正常速度，规则一句讲完
SLOW: 爽点爆点（出货/结算/突破/打脸）→ 全场唯一放慢的镜头
```

### 爆点最少 5 拍（SLOW 镜头的身体递进）

出货/结算镜头必须拆成 ≥5 个递进拍，每拍一个身体/画面反应：

```text
拍1 面板亮第一行关键奖励 → 瞳孔一缩
拍2 第二行 → 呼吸停半拍
拍3 后续行 → 指节攥白 / 手心出汗
拍4 最大奖励 → 整个人愣住 / 腾地坐直
拍5 回神 → 压不住的笑 / 肌肉扭曲 / 咬牙压吼
拍6（可选）消化 → 摸物件/看手腕，一句内心台词收
```

禁止：

```text
爆点一句带过（"模拟结束，他升到了二阶" = FAIL）
爆点只写心理不写身体（"他很激动" = FAIL）
```

## 3. 面板直给（S3 输入包必带）

金手指规则在正文中必须：**整块面板甩出 + 一句人话总结**。

```text
【系统面板……】完整列出（属性/规则）
+ 一句旁白/台词总结规则（"模拟结束继承全部，多活一年多一次"）
```

禁止：

```text
把规则拆散到三四个自然段里解释
用"他明白了，这意味着……"式转述代替面板
```

## 4. 信息承载顺序（对白优先）

本规约写作：**对白 > 面板 > 短叙述**。

```text
-DIALOGUE_FIRST: 能用对白带的信息（处境/价格/压迫/关系）不写进叙述
-SHORT_NARRATIVE: 叙述只做跳板（"两人过跳板""夜里他数钱"），不做心理铺陈
```

开场第一句默认是**对白**（人声+同伴/冲突），不是环境描写。

## 5. 目标宣言镜头（每章至少一个）

模拟器文靠"要干翻谁"驱动，每章 1-2 个目标镜头：

```text
DECLARE_TARGET: 明确对象+狠话+立刻行动（"赵疤，洗干净脖子等着。开始模拟！"）
禁止温和版："他心想以后要努力"（= FAIL，太软）
允许守护+复仇双目标（先守护后算账）
```

## 6. 句子形态基线

```text
短句为主，一句一信息；关键处允许独立成行的短句（"又挨打了。""这波，赌了。"）
语气词/拟声适量（嘿嘿/叮/腾），不用刻意避
心理外放可带感叹号，克制使用（每章 ≤10 个"！"）
```

## 6.5 章节肉块清单（每章必含，母本对齐）

母本真实单章 1600-1800 汉字（六大六子前10章实测）。章节不是"事件流水"，而是**功能块组合**。每章必须包含以下肉块（缺块 = 章节偏瘦，回 S2 补）：

```text
B1 金手指推演块（≥120字）：主角拿到/使用金手指后，当场算价值+定规划
   （"牌库没锁卡/活久=多赚/能翻身/干翻谁"，网文老读者视角拆解）
B2 身世/背景块（≥80字，可跨章轮换）：本章触发前的共情锚
   （屠村/队友之死/妹妹的病/曾经的伤——给读者"他为什么拼"的理由）
B3 面板讲解块：面板出现时逐条点评关键项（不只是一行属性）
   （"三角肌让肩膀力量提升""耐饿减少不适"式，规则讲透=期待感足）
```

字数门（对齐母本实测）：

```text
CHAPTER_HANZI_TARGET: 1700-1900（正文区汉字）
CHAPTER_HANZI_FLOOR: ≥1500
低于红线 → 回 S3 补肉块（推演/身世/面板/爆点铺陈），不是注水
```

## 6.6 金手指执行不是快进（模拟执行=小故事）

模拟/系统事件在章内不能只是"光幕快进+结算"。至少要有 1-2 个**真实展开节点**：

```text
- 选择节点：主角面对活法/词条/路线选项时的取舍与理由（他为什么这么选）
- 危机节点：模拟或系统事件中出现一次具体危机+主角的具体应对（逃/搏/忍）
- 后果节点：事件如何改变主角下一步的判断
```

禁止一整章全是"【第X年：……】【第X年：……】"式纯快进流水（母本第1章后半就是一段完整小故事：逃河/大春放火/河妖伏笔）。

## 7. 标点与 normalize 联动

- `"……`（引号+省略号开头）→ 已修 normalize，保留（犹豫/未尽功能）
- 正文中其他省略号会被 normalize 转逗号（deslop 既定策略，符合"不保留省略号"）
- 禁用 em-dash（normalize 会改）

## 8. 硬复核新增项（S3 J 项扩展）

在 J1-J5 基础上增加模拟器文专项：

```text
J6 BURST_SHOT: 爆点是否 ≥5 拍且有身体反应？FAIL 则回剧情块补拍
J7 VOICE_PRESENT: 开篇 300 字内是否有对白/同伴在场？FAIL 则回人物块
J8 PANEL_DIRECT: 金手指规则是否面板直给+一句总结？FAIL 则回输入包
J9 DECLARATION: 是否有目标宣言镜头？FAIL 则回剧情块补宣言
```

## Memory line

> **模拟器文 = 强声口 + 对白开场 + 面板直给 + 爆点五拍 + 宣言驱动。规则全部由上游输入承担，不碰 Story Compose 黑盒。**
