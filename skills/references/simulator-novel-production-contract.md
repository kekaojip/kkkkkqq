# Simulator Novel Production Contract｜模拟器文生产规约

> status: production-main
> role: 本书系工作流的专用生产规约（模拟器文 / 系统流 · 番茄向）
> applies_to: S1 / S2 / S3 全链（Story Compose 黑盒内部不动，本规约只在上游输入与硬复核生效）
> basis: 母本《一年抽取一词条，模拟的也可以？》第1章 + 《高武：人到中年…》第1章 拆解结论
> authority: TARGET 真值 > 本规约 > 泛网文默认

## 0. 为什么有这个文件

模拟器文有自己的读者契约：**面板、出货、赌狗心态、快节奏、强声口**。通用"自然好读"约束写不出这种书。本规约把模拟器文必须的写法要求固化到上游（剧情块/人物块/输入包），让 Story Compose 原包拿到"能写出模拟器文"的输入，而不是靠生成器自由发挥。

## 1. 人物声口契约（S2 人物块必带）

主角必须是"网文读者"人设（番茄/起点老读者），满足：

```text
VOICE_PLAYFUL: 口语化、会玩梗（"这波血赚""赌了""欧了""非了"），密度适中不尬
VOICE_EXPRESSIVE: 心理外放，狂喜/崩溃直接写，不用"压住情绪"式含蓄叙事
VOICE_META: 对系统文/模拟器文套路有认知，能自己解说金手指（meta 幽默，一处一章足够）
VOICE_COMRADE: 必须有至少一个同伴角色（话痨/憨厚/仗义），同伴是常驻互动对象；**不要求每章由他对白开场**（开头手法见 §4.1）
```

禁止：

```text
苦情隐忍型主角（模拟器文要的是爽不是苦）
全程无心理活动、无吐槽的"行动机器"
只有主角没有"活人配角"
```

## 2. 剧情块节拍（S2 剧情块必带）

模拟器文章节节奏，必须标注每个镜头的快慢：

```text
FAST: 铺垫/日常/压榨/背景 → 一段带过，不恋战
MID: 触发/面板/决策 → 正常速度，规则一句讲完
SLOW: 爽点爆点（出货/结算/突破/打脸）→ 全场唯一放慢的镜头
```

### 爆点最少 5 拍（SLOW 镜头的身体递进）

出货/结算镜头必须拆成 ≥5 个递进拍，每拍一个身体/画面反应：

```text
拍1 面板亮第一行关键奖励 → 瞳孔一缩
拍2 第二行 → 呼吸停半拍
拍3 后续行 → 指节攥白 / 手心出汗
拍4 最大奖励 → 整个人愣住 / 腾地坐直
拍5 回神 → 压不住的笑 / 肌肉扭曲 / 咬牙压吼
拍6（可选）消化 → 摸物件/看手腕，一句内心台词收
```

禁止：

```text
爆点一句带过（"模拟结束，他升到了二阶" = FAIL）
爆点只写心理不写身体（"他很激动" = FAIL）
```

## 3. 面板直给（S3 输入包必带）

金手指规则在正文中必须：**整块面板甩出 + 一句人话总结**。

```text
【系统面板……】完整列出（属性/规则）
+ 一句旁白/台词总结规则（"模拟结束继承全部，多活一年多一次"）
```

禁止：

```text
把规则拆散到三四个自然段里解释
用"他明白了，这意味着……"式转述代替面板
```

## 4. 信息承载顺序（对白优先）

本规约写作：**对白 > 面板 > 短叙述**。

```text
-DIALOGUE_FIRST: 能用对白带的信息（处境/价格/压迫/关系）不写进叙述
-SHORT_NARRATIVE: 叙述只做跳板（"两人过跳板""夜里他数钱"），不做心理铺陈
```

### 4.1 开头手法（入戏第一拍，禁止套路化）

开篇不强制对白。唯一硬要求是**第一拍必须快速入戏**（让读者立刻进入某事，禁止纯氛围/纯铺垫开场）。手法不限，按本章需求任选：

```text
OPENING_DIALOGUE  对白开场（重冲突/关系在场时用）
OPENING_EVENT     事件直入（变故/爆发/命令砸下来）
OPENING_OBJECT    物件/画面特写（关键道具出场，带出信息）
OPENING_CONTINUE  承接上章（"三天后""第二日""那晚之后"）
OPENING_PANEL     系统面板/模拟光幕承接（系统事件延续时）
OPENING_THOUGHT   一句内心独白/判断直接进场
```

硬规则：

```text
按章节类型给定默认与例外（母本前200章实测）：
  SIM 章：默认 PANEL 开场 + PANEL 结尾（母本 76% 章如此，连续数十章同型合法）
  REALITY 章：默认 EVENT 开场 + 自由结尾（OTHER/台词/定格/问句）
  MIX 章：任选
SPICE_RULE: SIM 章连续 ≥10 章纯面板开场时，可穿插 1 章 EVENT/DIALOGUE 开场换气（母本 7% 切换率）
纯环境/氛围/天象开场（"夜很深""风很冷"起手）仍为 FAIL
```

禁止"每章都从人物对话切入"的默认动作（对话开场仅适用于 REALITY/MIX 章冲突场景，且不得连续两章使用）。

### 4.2 结尾手法（断章自由，按章节类型）

章末断在哪由本章内容决定。允许：

```text
ENDING_HOOK       悬念钩子（一个问题/一个反常现象/一句话没说完）
ENDING_FROZEN     定格画面（一个画面收住：火光/背影/药碗/窗外）
ENDING_LINE       一句台词收尾（宣言/吐槽/承诺都行）
ENDING_ACTION     行为收束（睡下/离开/喝药/开练）
ENDING_AFTERMATH  爆点之后的余波/反应回合
ENDING_NATURAL    自然断章（事情讲到这儿就停，无钩子也可，母本第4章先例）
ENDING_BRANCH     选择分支停在"请做出选择"
ENDING_PANEL      系统面板收尾（SIM 章默认合法：结算/状态/机会提示，母本 82% SIM 章如此）
```

硬规则：

```text
SIM 章：PANEL 结尾为默认，不判模板化；需要在结算面板后加一句画面/台词余韵也可
REALITY 章：禁止默认面板结尾；用台词/定格/问句/自然断
【可模拟人生：N】/【是否开始下一次模拟】/“来！”仅在 SIM 章尾部合法出现
无钩子自然断章是合法节奏选择，不视为缺陷
```

外力标记：剧情块必须标注【开头拍型】与【结尾拍型】+【CHAPTER_TYPE】；S3 J14 复核（见 prose-preparation §9.3）。

## 5. 目标宣言镜头（每章至少一个）

模拟器文靠"要干翻谁"驱动，每章 1-2 个目标镜头：

```text
DECLARE_TARGET: 明确对象+狠话+立刻行动（"赵疤，洗干净脖子等着。开始模拟！"）
禁止温和版："他心想以后要努力"（= FAIL，太软）
允许守护+复仇双目标（先守护后算账）
```

## 6. 句子形态基线

```text
短句为主，一句一信息；关键处允许独立成行的短句（"又挨打了。""这波，赌了。"）
语气词/拟声适量（嘿嘿/叮/腾），不用刻意避
```

### 6.1 情绪外放（母本对齐：喊出来，不是说出来）

母本前200章实测：感叹号中位 24（SIM 与 REALITY 章均约 22-24），范围 1-86（爆发章 50-86，转场章可个位数）。模拟器文的情绪必须是"喊"的，但**按章节类型浮动，不设统一下限**：

```text
EXCLAMATION_REFERENCE: 每章中位参考 24（SIM/REALITY 适用）
EXCLAMATION_RANGE: 10-50 为正常浮动区；爆点/打脸章可冲到 60+；转场/铺垫章允许 <10
EXCLAMATION_HARD_RULE: 情绪节点必须外放——出货狂喜"我靠！！血赚！！"、打脸"让你狗仗人势！"、
崩溃"这日子没法过了！！"、吐槽"统子你给力点啊！！"；不得把情绪写成"他很激动/他压住狂喜"
```

```text
禁止把情绪写成"叙述"：
"他很激动" / "他压住狂喜"（= FAIL，母本是"憋得肌肉都在抽搐！"）
"他平静地说"（情绪节点禁止冷静腔）
```

（感叹号数量本身不设死门槛；关键在情绪节点是否外放。）
```

> 检测器已实测：高密度感叹号 + 面板行 0 blocking，不会误伤。deslop 的 advisory 中情绪类提示按"网文功能性保留"处理。

## 6.2 系统互动浓度（母本对齐：按章节类型浮动）

母本前200章实测：SIM 章（76%）面板 66-96 行/章；REALITY 章（22%）面板 0-1 行/章。**面板量由章节类型决定，不设统一下限**：

```text
CHAPTER_TYPE: SIM | REALITY | MIX（剧情块必须标注，对应 §4 可拍性门 §5.4）

SIM 章（模拟/面板主导）：面板 50-95 行【】系统内容；≥2 个系统互动场景
REALITY 章（现实/事件主导）：面板 0-10 行合法，不强制凑面板；至少 1 个现实事件推进
MIX 章：面板 15-40 行

SYSTEM_SCENES（SIM 章必选 ≥2，从以下取）：
  ① 抽取/抽卡过程（光团、光点、概率、欧非）
  ② 选择分支（"请做出选择：1/2/3"+主角取舍理由）
  ③ 模拟光幕（每一年事件 + 词条/奖励出现）
  ④ 结算清单（逐行亮出 + 身体反应 + 价值盘点）
  ⑤ 系统吐槽（主角对统子说话："统子你给力点啊！"）
  ⑥ 指引任务/面板升级（新功能开放）
```

REALITY 章 0 面板合法（母本第8章先例），不得因"面板少"判 FAIL；衡量其质量的是现实事件推进与人物反应。

### 6.3 对白比例（软提醒，不设硬门）

母本前200章实测：对白占比 10%-58% 自由摆荡（SIM 中位 38% / REALITY 中位 41%），与质量无直接相关。**不设达标区间**：

```text
对白占比：不设硬门；由章节内容自然形成（REALITY 打脸章可 50%+，光幕章可 25% 以下）
软提醒：若整章对白占比 >55% 且无系统互动/推进性叙述，检查是否变成纯对话灌水
"人机对话"（吐槽统子/选择自问）是好东西，应占对白的重要部分
人对人对话只承担：关系、信息、冲突；能用系统互动/内心外放的不用人物对话替代
```

## 6.5 章节肉块清单（每章必含，母本对齐）

母本真实单章 1600-1800 汉字（六大六子前10章实测）。章节不是"事件流水"，而是**功能块组合**。每章必须包含以下肉块（缺块 = 章节偏瘦，回 S2 补）：

```text
B1 金手指推演块（≥120字）：主角拿到/使用金手指后，当场算价值+定规划
   （"牌库没锁卡/活久=多赚/能翻身/干翻谁"，网文老读者视角拆解）
B2 身世/背景块（≥80字，可跨章轮换）：本章触发前的共情锚
   （屠村/队友之死/妹妹的病/曾经的伤——给读者"他为什么拼"的理由）
B3 面板讲解块：面板出现时逐条点评关键项（不只是一行属性）
   （"三角肌让肩膀力量提升""耐饿减少不适"式，规则讲透=期待感足）
```

字数门（当前生产口径；母本统计仅作参考）：

```text
CHAPTER_HANZI_TARGET: 1900-2500（正文区汉字；整个区间均为正常目标）
CHAPTER_HANZI_FLOOR: ≥1500
LENGTH_REPAIR_WITHIN_TARGET_RANGE: forbidden
不要为了贴近1900提前收尾，也不要为了贴近2500注水。
低于硬底线 → 回 S3 检查是否缺肉块（推演/身世/面板/爆点铺陈）；剧情已经完整时，不为凑目标字数机械补写。
```

## 6.6 金手指执行不是快进（模拟执行=小故事）

模拟/系统事件在章内不能只是"光幕快进+结算"。至少要有 1-2 个**真实展开节点**：

```text
- 选择节点：主角面对活法/词条/路线选项时的取舍与理由（他为什么这么选）
- 危机节点：模拟或系统事件中出现一次具体危机+主角的具体应对（逃/搏/忍）
- 后果节点：事件如何改变主角下一步的判断
```

禁止一整章全是"【第X年：……】【第X年：……】"式纯快进流水（母本第1章后半就是一段完整小故事：逃河/大春放火/河妖伏笔）。

## 7. 标点与 normalize 联动

- `"……`（引号+省略号开头）→ 已修 normalize，保留（犹豫/未尽功能）
- 正文中其他省略号会被 normalize 转逗号（deslop 既定策略，符合"不保留省略号"）
- 禁用 em-dash（normalize 会改）

## 8. 硬复核新增项（S3 J 项扩展）

在 J1-J5 基础上增加模拟器文专项：

```text
J6 BURST_SHOT: 爆点是否 ≥5 拍且有身体反应？FAIL 则回剧情块补拍
J7 VOICE_PRESENT: 开篇 300 字内是否有对白/同伴在场？FAIL 则回人物块
J8 PANEL_DIRECT: 金手指规则是否面板直给+一句总结？FAIL 则回输入包
J9 DECLARATION: 是否有目标宣言镜头？FAIL 则回剧情块补宣言
```

## Memory line

> **模拟器文 = 强声口 + 面板直给 + 爆点五拍 + 宣言驱动 + 开结尾多样（入戏第一拍/断章自由）。规则全部由上游输入承担，不碰 Story Compose 黑盒。**
